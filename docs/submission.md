# Соответствие заданию и формат сдачи

Документ сопоставляет содержимое репозитория с требованиями кейса
«DevOps (MTC ENGINEER HACK)». Публичность размещенного репозитория
проверяется отдельно после переноса на Git-хостинг.

## Обязательные компоненты

| Требование | Реализация в репозитории | Проверка |
| --- | --- | --- |
| Kubernetes на Ubuntu 24.04 | kubeadm 1.34.3, containerd и Calico; [Ansible](../ansible/README.md) | `make health ENV=ubuntu` |
| HTTP-приложение с проверяемым ответом | [Nginx](../deploy/app/), ответ `Hello World!`, access/error-логи | HTTP-команды в [README](../README.md#проверка-приложения) |
| Kubernetes Gateway API | Traefik, GatewayClass, Gateway, HTTPRoute; [конфигурация](../deploy/gateway/) | `make verify-release ENV=ubuntu` |
| Метрики Prometheus | [kube-prometheus-stack и ServiceMonitor](../deploy/monitoring/) | Targets и PromQL в [README](../README.md#проверка-мониторинга) |
| Сбор логов Fluentd или Filebeat | [Fluentd и Loki](../deploy/logging/) | Поиск access/error-записей в [README](../README.md#проверка-логирования) |
| Автоматизация и повторный запуск | [deploy.sh](../scripts/deploy.sh), Ansible, Helm, Python | `make verify-idempotency ENV=ubuntu` |
| Воспроизведение без инфраструктуры автора | Примеры окружения, публичные образы, версии и контрольные суммы | [Установка](../README.md#установка) на выделенной VM |
| Документация и ограничения | README, архитектура, эксплуатация, результаты проверок и паспорт | Разделы и ссылки ниже |

## README

[README.md](../README.md) содержит описание и схему архитектуры, версии
технологий и Kubernetes, реализацию Gateway API, требования к среде,
пошаговую установку, команды запуска и отдельные инструкции проверки
приложения, мониторинга и логирования. Реализованные дополнительные
возможности и ограничения перечислены отдельными разделами.

## Паспорт проекта

[Паспорт PDF](passport.pdf) и его [исходник HTML](passport.html) содержат:

1. Архитектуру, схему, состав решения, версии и проверенную ОС.
2. Обязательные компоненты: реализацию, обоснование и способ проверки.
3. Дополнительные возможности: реализацию, обоснование и способ проверки.
4. Результаты, ограничения, главную особенность, сложное техническое решение
   и предложения по развитию.

Раздел о развитии обязателен по заданию. Он явно отделен от реализованных
возможностей и указывает необходимые ресурсы. Паспорт занимает не более
четырех страниц; допустимый размер PDF или DOC/DOCX — до 15 МБ.

HTML использует печатный формат A4. Для получения PDF откройте его в браузере,
выберите «Сохранить как PDF», масштаб 100%, включите фоновую графику
и отключите колонтитулы браузера с датой и адресом файла.

## Репозиторий и публикация

По заданию решение располагается в основной ветке `main`. Репозиторий
должен быть публичным, клонироваться без авторизации и оставаться доступным
до публикации списка финалистов. После размещения проверяется клонирование
из среды без сохраненных учетных данных:

```bash
GIT_TERMINAL_PROMPT=0 git -c credential.helper= clone --branch main --single-branch <HTTPS_URL> /tmp/mts-stack-public-check
```

Замените `<HTTPS_URL>` на адрес опубликованного репозитория и используйте
свободный каталог назначения. Проверка клонирования не заменяет проверку
установки по README.

В Git входят исходники, конфигурации-примеры, документация, паспорт
и сводки проверок. Локальные окружения, `.state/`, `.cache/`, `.venv/`,
`artifacts/`, kubeconfig и приватные ключи исключены через
[.gitignore](../.gitignore). Перенос через Git включает только отслеживаемые
файлы; копия всего рабочего каталога также содержит игнорируемые данные.
Пароли, токены, приватные ключи и персональные данные запрещены заданием.

## Архив для сдачи

| Элемент | Требование |
| --- | --- |
| Архив | ZIP или RAR, до 18 МБ, имя — фамилия участника при регистрации |
| `Ссылка.txt` | Только URL актуальной ветки `main` публичного репозитория |
| `Паспорт.pdf` | Копия `docs/passport.pdf`; допустимое имя альтернативного документа — `Паспорт.doc` |

Архив и файл со ссылкой формируются после появления окончательного
публичного URL. Срок из задания — **4 октября, 23:59**; после него изменения
в сдаваемой ветке запрещены. Это условие сдачи, а не дата выполнения работ.
